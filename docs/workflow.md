# 标准工作流

## 根据输入调整流程

输入可以是一个主题、零散笔记、报告、逐页准备好的 Markdown，或几种形式的组合。agent 分别评估内容与视觉的准备程度，复用已给出的决策、准确文案和讲稿，在扩展内容前只问真正影响结果的问题。受众、目的、已有知识、语气、场合、语言、时长与范围都可能改变内容；这些是例子，不是固定问卷。质量优先。

## 同时规划整套内容、视觉与讲稿

昂贵生图前，审核一份简洁的整套方案：故事线与各页角色、准确的可见文案和关键数值、视觉对象/关系/大致布局、素材与保真要求、重复使用的视觉身份、编号及依赖关系。建议新增的内容和缺少的证据要明确标出，不能编造公司事实或统计数据。

此时就用演示语言起草讲稿。它应像演讲者在房间里向大家解释：第一人称的亲切感、具体场景、日常词语、以空行分隔的思考节拍、自然连接词和有目的的过渡。长度适配讲话时间。保留已有讲稿，显著改写要单独标出。必要时先用一段代表性讲稿校准声音，再按例外审核整套讲稿。

## 锁定风格、比例与可执行的生图方式

可从十二种内置风格、个人风格或用户参考中选择；通常推荐少量相关选项。参见[风格与个人风格库](styles.md)。重复视觉身份保持一致，各页布局可按角色变化。

先锁定 16:9、4:3 或 3:2，再选能实际表达比例并传入必要图片的后端。检查当前工具 schema 与实际像素。Cursor GenerateImage 只用于 3:2 像素；enum 缺少 3:2 时可能要用合法的横向参数。gpt-image-2 路径在 schema 支持 size 时使用 2560x1440、2560x1920 或 2400x1600。比例错误应拒绝，不能拉伸或裁剪。

后端与完整参数保持已审批状态。CLI 路径需明确批准无图片的 generate 与有参考图片的 edit 操作策略；受管理任务通过适配器准确传递参数和所有已验证图片，不能用纯文字批处理重放任务。

风格、比例、后端/参数、代表样张策略、输出方式/标题与审核策略都在草案中先确定，再一起确认。内容、视觉、讲稿、输出方式/落地页标题及审核策略一起确认。完整材料只补真正的缺口，不规定每页要点数量，也不逐页重复访谈。修改时审核受影响的范围与依赖页，避免整套重做。

## 批量生产前校准

方案与讲稿确认后，生成或复用合适的代表性内容样张。用户接受实际外观及适用性后才批量生产。额外样张必须有实质视觉理由。已接受的风格参考字节保持不变，修复样张作为最终内容页的图片不会替换公共参考。未通过的校准样张可以先修复再接受。

## 生成、检查与审核

编译绑定审批的任务。环境支持时，每页由一个工作 agent 处理，主 agent 负责内容、状态、QA 和最终文件。工作 agent 保留准确文案、数值、素材及关系，排版装不下时报告问题，不能自行改内容。

后续生产前先检查首批。逐页检查后，再看整套的顺序、编号、共享视觉及讲稿过渡。孤立渲染缺陷在当前视觉约定内可自动定向修复一次，更多尝试需真实授权。首批反复失败时暂停，先解决共同原因。

默认采用集中审核：常规成功批次继续完成，再由用户一次审核当前整套图片并指出例外。也可选择严格逐批审核。agent QA 与用户接受图片是不同步骤，不能制造用户确认。

## 组装与交付

受管理脚本要求当前有效的内容/讲稿/策略决策、素材与样张字节、编译输入、完成结果、逐页/整套 QA 和用户对当前图片的确认。事实、素材或关系变化也会使受影响的讲稿失效；仅修改讲稿可复用当前图片。最终大纲和讲稿从已确认方案派生。

使用先前确认的无模板、Medavis 或两者，以及落地页标题。无模板为 N 个内容页；Medavis 使用匹配比例的三页模板，输出落地页 + N 个内容页 + 结束页（N+2），内容备注偏移一页。交付列出实际路径、页数、后端、讲稿及局限。页面是图片，文字和图表不能作为独立对象编辑。

历史的 v2 之前手动任务或纯图片目录须显式使用 `--legacy-unmanaged`，不能绕过受管理任务审批。自定义或调整过的风格在接受后可存入个人风格库。
