# 표준 워크플로

## 입력에 맞게 진행하기

주제, 거친 메모, 보고서, 페이지별 Markdown 또는 이들의 혼합으로 시작할 수 있습니다. agent는 내용과 시각 자료의 준비 상태를 따로 평가하고, 이미 제공한 결정과 정확한 문구·발표 대본을 재사용합니다. 내용을 확장하기 전에 결과에 영향을 주는 질문만 합니다. 청중, 목적, 사전 지식, 어조, 발표 환경, 언어, 시간과 범위는 예시이며 고정 질문지가 아닙니다. 품질을 우선합니다.

## 덱 전체의 내용, 시각 구성과 대본 계획하기

비용이 큰 이미지 생성 전에 간결한 전체 계획을 검토합니다. 이야기와 페이지 역할, 정확한 표시 문구와 핵심 수치, 시각 객체·관계·대략적인 배치, 원본 자료와 보존 요구, 반복되는 시각 정체성, 번호와 의존 관계를 포함합니다. 제안한 추가 내용과 부족한 근거를 구분하며 회사 사실이나 통계를 만들지 않습니다.

이 단계에서 발표 언어로 대본을 작성합니다. 발표자가 방 안의 사람들에게 설명하듯 1인칭의 따뜻함, 구체적인 장면, 일상 어휘, 빈 줄로 나눈 생각 단위, 자연스러운 연결과 목적 있는 전환을 사용합니다. 길이는 발표 시간에 맞춥니다. 기존 대본을 보존하고 큰 수정은 따로 제안합니다. 필요하면 대표 대본으로 말투를 맞춘 뒤 전체 대본의 예외를 검토합니다.

## 스타일, 비율과 실행 가능한 생성 방식 고정하기

열두 가지 내장 스타일, 개인 스타일 또는 제공한 참고 자료 중에서 선택하며 보통 관련 후보 몇 개를 추천합니다. [스타일과 개인 스타일 라이브러리](/ko/styles.md)를 참고하세요. 반복되는 정체성은 유지하고 페이지 역할에 따라 배치는 달라질 수 있습니다.

16:9, 4:3 또는 3:2를 먼저 고른 뒤 그 비율과 필요한 이미지 입력을 실제로 지원하는 백엔드를 선택합니다. 현재 도구 schema와 생성 픽셀을 검사합니다. Cursor GenerateImage는 3:2 픽셀에만 사용하며 enum에 3:2가 없으면 허용된 가로 인자가 필요할 수 있습니다. gpt-image-2 경로는 size를 지원할 때 2560x1440, 2560x1920 또는 2400x1600을 사용합니다. 잘못된 비율은 거부하며 늘리거나 자르지 않습니다.

백엔드와 전체 설정을 승인 상태로 유지합니다. CLI는 이미지 없는 generate와 참고 이미지가 있는 edit의 작업 정책을 명시적으로 승인합니다. 관리 작업은 어댑터로 정확한 설정과 검증한 모든 이미지를 전달하며 텍스트 전용 배치로 재생하지 않습니다.

스타일, 비율, 백엔드·설정, 대표 샘플 전략, 출력 방식·제목과 검토 정책은 통합 승인 전에 초안에서 정합니다. 내용, 시각 구성, 대본, 출력 방식·랜딩 제목과 검토 정책을 함께 승인합니다. 완성된 자료는 실제 빈틈만 보완하며 페이지별 글머리표 수나 반복 면담을 강제하지 않습니다. 수정 시 영향을 받는 범위와 관련 페이지를 검토합니다.

## 전체 생성 전에 샘플 검증하기

계획과 대본 승인 후 적절한 대표 콘텐츠 샘플을 생성하거나 재사용합니다. 실제 모양과 적합성을 승인한 뒤 전체 생성을 진행합니다. 추가 샘플에는 실질적인 시각적 이유가 필요합니다. 승인한 스타일 참고 이미지의 바이트는 유지하며 샘플의 최종 콘텐츠 페이지를 수정해도 공유 참고 자료는 바꾸지 않습니다. 실패한 샘플은 승인 전에 수정할 수 있습니다.

## 생성, 검사와 사용자 검토

승인에 연결된 작업을 컴파일합니다. 가능한 환경에서는 작업 agent 한 명이 한 페이지를 담당하고 주 agent가 내용, 상태, QA와 최종 파일을 관리합니다. 작업 agent는 정확한 문구, 수치, 자료와 관계를 유지하며 내용이 들어가지 않으면 임의로 다시 쓰지 않고 문제를 보고합니다.

후속 생성 전에 첫 배치를 검사합니다. 각 이미지뿐 아니라 전체 순서, 번호, 공유 시각 요소와 대본 전환을 확인합니다. 개별 렌더링 결함은 현재 시각 계약 안에서 한 번 자동 수정할 수 있고 추가 시도에는 실제 승인이 필요합니다. 첫 배치에서 반복 실패하면 멈추고 공통 원인을 해결합니다.

기본은 통합 검토입니다. 정상 배치는 계속 진행하고 사용자가 현재 전체 이미지를 검토하며 예외를 지정합니다. 엄격한 배치별 검토도 선택할 수 있습니다. agent QA와 사용자의 이미지 승인은 별개이며 사용자 승인을 만들어낼 수 없습니다.

## 조립과 전달

관리 스크립트는 현재 유효한 내용·대본·정책 결정, 원본·샘플 바이트, 컴파일 입력, 완료 결과, 페이지별·전체 QA와 현재 이미지에 대한 사용자 승인을 요구합니다. 사실·원본·관계 변경은 관련 대본도 무효화하지만 대본만 수정하면 현재 이미지를 재사용합니다. 최종 개요와 대본은 승인한 계획에서 파생됩니다.

이미 승인한 템플릿 없음, Medavis 또는 둘 다와 랜딩 제목을 사용합니다. 일반 출력은 콘텐츠 N페이지이며 Medavis는 비율에 맞는 3페이지 템플릿으로 랜딩 + 콘텐츠 N페이지 + 엔딩(N+2)을 만듭니다. 콘텐츠 노트는 한 페이지 밀려 연결됩니다. 실제 경로, 페이지 수, 백엔드, 대본과 한계를 전달합니다. 각 페이지는 이미지라 텍스트·차트가 개별 편집 객체가 아닙니다.

v2 이전 수동 작업이나 이미지 폴더는 `--legacy-unmanaged`를 명시해야 하며 관리 작업 승인을 우회할 수 없습니다. 사용자 지정·수정 스타일은 승인 후 개인 라이브러리에 저장할 수 있습니다.
