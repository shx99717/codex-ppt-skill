# 设计理念

Codex PPT Skill 里面放了我对 AI 做 PPT 的一些思考。

AI 做 PPT 最重要的不是快，而是流程可控，做出来可用。

所以我把流程拆成了几步：

1. 分别评估可复用内容与视觉准备程度，复用已知决策，只澄清真正影响结果的意图。
2. 同时起草准确文案、视觉、素材、共享身份、故事与依赖及自然讲稿，标出建议与缺少的证据。选择或复用风格，锁定比例、可用后端及参数/图片输入操作，并确定代表样张、输出方式/标题和审核策略。
3. 按例外集中确认完整内容、视觉、讲稿、生图方式与输出方案，再生成或复用并接受代表性样张。
4. 编译已审批任务并生成整套，检查首批和完整顺序。孤立渲染问题可自动定向修复一次，更多尝试需授权。默认集中审核当前图片，也可选择严格逐批审核。
5. 复核当前输入、图片、讲稿与确认记录，组装先前确认的无模板/Medavis/两者输出。无模板为 N 页，Medavis 为 N+2，内容备注偏移一页。可选择保存自定义或调整后的风格。

## 为什么默认先做图片式 PPT？

因为不是所有场景都需要可编辑。如果只是技术分享、课程笔记、读书分享、论文解读或不那么正式的汇报，整页图片式 PPT 其实已经够用，而且视觉统一性更好。

如果一开始就把“生成 PPT”和“转可编辑 PPT”强行耦合在一起，流程会变得很重：前期还在反复改大纲、改风格、改样张，就引入编辑结构还原，反而更慢、更贵、更难控。

所以我把它拆成两个 skill：

- 一个负责生成高质量图片式 PPT
- 另一个负责在需要时，把纯图 PPT 再转换成可编辑 PPT

先把内容和视觉方向聊清楚，确认生成结果可控，再考虑要不要转成可编辑，我觉得更稳。

## 针对社区反馈做的优化

这个 skill 里还做了一些针对社区反馈的优化：

- 支持 Codex 会员内置生图能力
- 也支持通过 API 接入生图模型
- 可以在 Codex、Claude Code、OpenClaw 等 agent 环境中使用
- 支持子智能体并行生成，加快多页 PPT 产出
- 内置多种风格引导，不会写高级 prompt 也能做出还不错的效果
- 支持参考图片、已有 PPT，生成类似风格的新 PPT
- 对论文图、实验结果图、截图这类用户原始图片做了保留优化，尽量避免 AI 重新乱画

我想做的不是“点一下出一个 20 页的 PPT”，而是把 AI 做 PPT 这件事变成一个更像真实工作流的过程：先确定结构，再确定风格，再确认样张，最后批量生成和自检。

输入可以是一个主题、完整逐页 Markdown，或准备程度不同的组合。skill 复用已完成的文案和讲稿，只澄清实质缺口，在昂贵生图前一起确认准确内容、视觉含义与自然讲稿。默认集中审核当前图片，也可严格逐批审核。图片渲染仍允许轻微差异。

讲稿在生图前用演示语言起草，像演讲者亲切地用日常语言解释：具体场景、以空行分隔的思考节拍、自然连接词与有目的的过渡。已有讲稿应保留，实质新增内容需确认。长度取决于讲话时间和复杂度。
