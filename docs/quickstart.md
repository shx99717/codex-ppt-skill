# 快速开始

## 适合谁

输入可以是一个主题、完整逐页 Markdown，或准备程度不同的组合。skill 复用已完成的文案和讲稿，只澄清实质缺口，在昂贵生图前一起确认准确内容、视觉含义与自然讲稿。默认集中审核当前图片，也可严格逐批审核。图片渲染仍允许轻微差异。

## 最短使用方式

先安装 skill，参见[安装与配置](installation.md)。然后，在 Codex 里直接使用这个 skill 进行 PPT 制作。

```text
请使用 codex-ppt skill，把 /path/to/article.md 做成 10 页左右的中文 PPT。
```

如果你已经知道风格和用途，可以写得更具体：

```text
请使用 codex-ppt skill，把这篇技术文章做成 12 页中文分享 PPT。风格偏清爽专业，适合内部技术分享；第 5 页必须使用我提供的架构图，第 8 页必须保留实验结果图。
```

## 第一次使用建议

- 讲稿在生图前用演示语言起草，像演讲者亲切地用日常语言解释：具体场景、以空行分隔的思考节拍、自然连接词与有目的的过渡。已有讲稿应保留，实质新增内容需确认。长度取决于讲话时间和复杂度。
- 不要跳过样张确认。先看一页效果，再批量生成整套 PPT。
- 如果某一页不满意，优先只改那一页，不要整套重做。
- 如果有参考 PPT、截图或 PDF，先让 agent 分析风格，再生成新 PPT。

## 生成结果

最终通常会得到：

- `outline.md`：PPT 大纲
- `origin_image/slide_XX.png`：每页正式图片
- `speech.md`：每页演讲备注
- `{PPT名称}.pptx`：最终 PowerPoint 文件

## 审核方式

输入可以是一个主题、完整逐页 Markdown，或准备程度不同的组合。skill 复用已完成的文案和讲稿，只澄清实质缺口，在昂贵生图前一起确认准确内容、视觉含义与自然讲稿。默认集中审核当前图片，也可严格逐批审核。图片渲染仍允许轻微差异。

受管理的 v2 脚本检查当前内容/讲稿/策略决策、素材与样张字节、编译输入、QA 和用户对当前图片的接受。历史手动或纯图片任务须显式使用 `--legacy-unmanaged`，不能绕过受管理审批。CLI 任务用 `run_slide_job.py` 准确传入已批准参数与全部图片。
